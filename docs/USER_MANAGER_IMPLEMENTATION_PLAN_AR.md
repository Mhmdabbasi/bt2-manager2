# خطة User Manager وإدارة الجلسات — bt2-manager2

## 1) الهدف والنطاق

تقديم تجربة تشغيل واضحة ومقسّمة بين HotSpot وUser Manager، مع قراءة فعلية لما يوفّره الراوتر وعرض الحقول كما وردت فقط. مرحلة التنفيذ الحالية تُنجز واجهات القراءة والمرشحات الآمنة، وتُبقي عمليات تعديل User Manager محظورة حتى اختبار التوافق على راوتر حقيقي لكل من RouterOS 6 وRouterOS 7.

المشروع محلي لمستخدم واحد. لا توجد منظومة POS أو مبيعات أو تحصيل مالي. بيانات الموزّع/نقطة التوزيع المقصودة هنا هي بيانات التخصيص المحلية المرتبطة بدفعة/قسيمة إن وُجد تطابق موثوق؛ لا تُنشأ معاملات بيع أو سجلات مالية.

## 2) مراجعة العقد والبنية

### مصادر الخدمة والتنقل

- User Manager له مدخل مستقل وصفحتان واضحتان: **Profiles** و**المستخدمون**.
- صفحة **الجلسات** موحّدة، وتجمع جلسات HotSpot الحية وسجل جلسات User Manager الذي يرسله الراوتر.
- الباقات واستوديو البطاقات وأرشيف الدفعات أدوات مشتركة، بينما عمليات HotSpot الحالية تظل في قسم HotSpot.
- لا تُعرض عمليات User Manager على أنها متاحة لمجرد وجود زر أو مسار API؛ واجهة المستخدم والـAPI كلاهما يلتزمان ببوابة التوافق.

### اختلافات RouterOS

- RouterOS 6: مسارات User Manager القديمة تحت `/tool/user-manager/...`؛ مسار ربط الملف بالمستخدم هو `/tool/user-manager/user/profile`، ويظهر اسم الحساب عادةً كـ`username` وحقول الجلسة القديمة مثل `from-time`, `user-ip`, `host-ip`.
- RouterOS 7: المسارات تحت `/user-manager/...`؛ إسناد الملفات عبر `/user-manager/user-profile` وحقول المستخدم تتضمن `name`، والجلسة تستخدم حقولاً مثل `started`, `ended`, `user-address`, `nas-ip-address`.
- وجود سجل الجلسات في User Manager يعتمد على تفعيل Accounting على NAS. لذلك غياب السجل لا يعني أن المستخدم غير نشط، ولا تُستنتج جلسة HotSpot من سجل UM أو العكس.
- مصدر التوافق المرجعي للتنفيذ هو عقد RouterOS الفعلي لكل إصدار، لا وثائق الإصدار 7 وحدها. أي حقل غير موجود أو غير مفهوم يعرض كـ«غير متاح» ولا تُملأ قيمته تخميناً.

### البيانات الحساسة

- قوائم القراءة تستخدم إسقاطاً صريحاً للحقول المسموح بها. لا يُطلب أو يُخزّن `password` أو `otp-secret` أو أسرار NAS.
- يتم تمييز معرف Calling-Station-ID كمعرّف أرسله الراوتر، لا كعنوان MAC مؤكّد في كل أنواع الخدمة.
- العنوان/المضيف الذي يعيده NAS لا يثبت طراز الجهاز أو نقطة الوصول. لا يُخترع اسم جهاز أو AP عند غياب مصدر موثوق.

## 3) المتطلبات وسلوك الواجهة

### صفحة مستخدمي User Manager

- عرض كامل الحسابات التي يعيدها الراوتر مع الاسم والحالة/التعطيل، المجموعة أو التعليق عند توفرهما، الملف الفعلي أو الملفات المسندة وحالتها ووقت انتهائها.
- المرشحات: الكل، مع جلسة نشطة، لديه ملف فعّال، ملف منتهي/مستهلك، معطّل؛ مع بحث بالاسم والملف والمعرّف والتعليق.
- عرض `download-used`, `upload-used`, `uptime-used` عندما يرسلها RouterOS 6. في RouterOS 7 لا تُعرض أرقام استخدام مستنتجة من جلسات Accounting على أنها إجمالي الحساب؛ يُشار لمصدرها بوضوح أو تترك «غير متاح».
- عند تطابق موثوق مع سجل محلي، يمكن عرض اسم الباقة/الدفعة والموزع ونقطة التوزيع. الحساب غير المرتبط يظل «غير مرتبط بسجل محلي»؛ لا يُنشأ ربط تخميني ولا POS.
- جميع الكتابات للمستخدم/ملفه/رصيده مؤجلة: لا إنشاء، ولا تعطيل، ولا إعادة شحن/إضافة باقة، ولا حذف.

### صفحة الجلسات الموحّدة

- HotSpot: قائمة الجلسات النشطة من `/ip/hotspot/active` مع المستخدم والخادم وIP وMAC المرسل ومدة الاتصال والبايتات المتاحة. واجهة HotSpot الحالية لا تعيد تاريخ الجلسات المنتهية؛ لذلك لا تعرض سجلاً تاريخياً مصطنعاً.
- User Manager: قائمة الجلسات التي أعادها UM، مع حالة active/status والتوقيتات والحركة وCalling-Station-ID وIP/NAS/port عندما تتوفر؛ يوضّح التنبيه أن سجل الجلسات يعتمد على Accounting.
- مرشحات الخدمة والحالة وبحث المستخدم/المعرّف/IP/NAS.
- إنهاء جلسة HotSpot النشطة متاح بتأكيد صريح بعد التحقق من أن المعرّف لا يزال ضمن القائمة النشطة.
- إنهاء جلسة UM يظل معطلاً حتى عبور بوابة توافق مستقلة على الإصدارين؛ لا تنفذ واجهة أو API أي أمر كتابة UM في هذه المرحلة.

## 4) مراحل التنفيذ وبوابات القبول

| المرحلة | العمل | معيار القبول |
|---|---|---|
| A — عقد القراءة والتنقل | تثبيت مسارات v6/v7، استبعاد الأسرار، فصل Profiles والمستخدمين وإضافة جلسات موحدة | لا توجد كتابة UM، والفروق بين الإصدارين ظاهرة في المحول والاختبارات |
| B — دليل المستخدمين | قراءة المستخدمين وإسنادات Profiles وعرض المرشحات والبيانات المحلية المرتبطة فقط | لا يُدّعى اكتمال القوائم أو الحقول عند فشل RouterOS؛ جميع الحقول غير المتاحة تبقى فارغة/موضحة |
| C — الجلسات | قراءة جلسات UM التاريخية/النشطة وجلسات HotSpot النشطة | الجلسة التاريخية تظهر فقط إذا أعادها الراوتر؛ غياب Accounting معروض بوضوح |
| D — عملية HotSpot الآمنة | إنهاء جلسة HotSpot نشطة بعد إعادة التحقق من المعرّف | تأكيد مستخدم، وعدم قبول ID لم يعد نشطاً |
| E — توافق User Manager للقراءة | اختبار عملي على RouterOS 6 و7 (المسارات والحقول والحالة والأعداد والأخطاء) | محضر اختبار منفصل لكل إصدار وعائلة جهاز/إصدار UM، بما في ذلك حالة Accounting متوقف |
| F — كتابة User Manager | تعطيل مستخدم، إنهاء جلسة UM، وإضافة/تجديد باقة بعد تصميم كل إجراء | **ممنوع قبل نجاح E لكل من RouterOS 6 و7**، واختبار أثر/تراجع وصلاحيات قبل فتح أي endpoint |

### مصفوفة التحقق المطلوبة قبل فتح كتابة UM

لكل من RouterOS 6 وRouterOS 7، يسجل الاختبار: إصدار RouterOS وحزمة user-manager، إصدارات المكتبة، المسارات والاستجابات الخام المنقّحة من الأسرار، قيم حقول المستخدم والملف والجلسة، حالة Accounting متوقف/مفعّل، قواعد انتهاء الملف، نتيجة تعطيل مستخدم، نتيجة إنهاء جلسة، ونتيجة إسناد/إضافة ملف. لا تكفي بيانات الاختبار الاصطناعية أو وثائق v7 لاجتياز هذه البوابة.

## 5) حالة التنفيذ في هذا الفرع

- **مكتمل سابقاً:** شاشة قراءة Profiles/limitations/relationships، حفظ لقطة التعريفات محلياً، اختبار محلل اصطناعي، وفصل صفحات HotSpot/كتالوج الخدمة.
- **منفذ في هذا التغيير:** دليل مستخدمي UM وإسنادات الملفات للقراءة، صفحة مستخدمين منفصلة بمرشحات البحث والحالة والملف وآخر تخصيص محلي، صفحة جلسات موحدة، وإنهاء جلسة HotSpot النشطة بعد إعادة التحقق من المعرّف. واجهة الكتابة إلى UM غير موجودة؛ إجراء إنهاء جلسة UM معطّل بوضوح.
- **غير مكتمل/مؤجل:** تحقق حقيقي من RouterOS 6 و7، سجلات الجهاز/AP الموثوقة، إجراءات كتابة UM، وربط توزيع المستخدمين ببيانات محلية إذا لم توجد قسيمة/دفعة مطابقة.
- **الاختبارات المتاحة حالياً:** `npm run typecheck && npm run build` نجح بعد التغيير، وفُحصت بنية Go بـTree-sitter (فحص نحوي فقط) واختبر استعلام الربط المحلي على SQLite مؤقتة. تعذر `go test ./...` لأن Go غير متوفر. بيئة المعاينة قد لا تحتوي خدمة API أو راوتر. لا يعلن أي اختبار راوتر حقيقي أو Windows/طباعة على أنه ناجح دون تشغيله.
