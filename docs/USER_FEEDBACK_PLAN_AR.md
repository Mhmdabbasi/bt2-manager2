# خطة تنفيذ ملاحظات التجربة الميدانية

> نطاق هذه الخطة: معالجة العيوب التي ظهرت على راوتر حقيقي، ثم إكمال سير الباقات والتوزيع والتوليد والقوالب والجداول. لا تُفتح كتابة User Manager قبل اجتياز بوابة توافق مستقلة لـRouterOS 6 و7. لا يوجد POS أو تحصيل مالي ضمن MVP.

## قواعد تنفيذ ثابتة

1. مكتبة الاتصال الوحيدة هي `github.com/Mhmdabbasi/routeros-api-Go`؛ لا نكتب محلل بروتوكول RouterOS بديلاً.
2. كل طلب إنشاء دفعة يجب أن يحفظ المطلوب، والمنفذ، والفاشل، وسبب كل فشل؛ لا تعرض الدفعة الجزئية على أنها مكتملة.
3. لا تعاد كتابة RouterOS بعد مهلة غامضة إلا بعد مصالحة باسم دخول فريد تثبت غياب المستخدم؛ لا إعادة محاولة عمياء.
4. أسعار الباقة وفرق الموزع بيانات تسعير/هامش فقط. لا مبيعات، فواتير، دفاتر إيراد، أو تحصيل.
5. كل ترقية قاعدة بيانات بمهاجرة جديدة؛ لا تعديل مهاجرة سبق إصدارها.

## المراحل وبوابات القبول

### P0 — إصلاحات موثوقية مانعة للتجربة
- [x] إصلاح تقديم ملفات CSS/JS على Windows باستعمال مسارات URL ذات `/`؛ أضيف اختبار handler لـMIME ومسار SPA و404 للملفات الناقصة.
- [x] نقل ورقة طباعة القسائم إلى portal منفصل عن واجهة التطبيق وإخفاء جذر التطبيق أثناء الطباعة مع وضع الورقة في تدفق المستند. (تنفيذ واجهة؛ اختبار PDF فعلي على Windows ما زال مطلوباً.)
- [x] حصر الورقة على العناصر النشطة الناجحة فقط وحساب الصفحات من عدد البطاقات في التخطيط؛ لا يصدر التطبيق ورقة ثانية من صفحة الواجهة. (اختبارات الأعداد والطباعة الفعلية ما زالت مطلوبة.)
- [x] إظهار القسائم الفاشلة وسببها، ومصالحة الكتابة الملتبسة ثم السماح بمحاولة إضافية واحدة فقط إذا ثبت غياب الاسم، مع مصالحة نهائية. (لم يُختبر بعد على RouterOS حقيقي؛ حالات 0 و1 و18 و20 و60 و61 ضمن P6.)

### P1 — نموذج الباقة وتسعيرها
- [x] اختيار نوع الخدمة `HotSpot` أو `User Manager` وتحميل الملفات بحسب النوع.
- [x] حقول سعر المستخدم/الموزع والهامش المحسوب والتحقق من الحدود في API.
- [x] خصائص الملف الظاهرة للقراءة فقط مع توضيح أنها لا تغيّر الراوتر.
- [x] واجهة تعديل/إيقاف الباقة وربط لقطة الأسعار والملف في سجل الدفعة؛ اختبار Go ما زال معلقاً لتوفر الأداة.
- [x] User Manager عرض/اختيار تخطيطي؛ الكتابة ممنوعة في الواجهة والـAPI حتى اجتياز v6/v7.

### P2 — سياسة الموزع
- [x] افتراضي إتاحة كل الباقات مع استثناءات سماح/منع وبادئة لكل باقة محفوظة بمعاملة.
- [x] واجهة تفعيل/إيقاف الموزع، دون تعديل حركات المخزون السابقة؛ اختبار Go على التطبيق ما زال مطلوباً.

### P3 — إعدادات التوليد (HotSpot)
- [x] اختيار الخدمة والباقة والمالك، البادئة، نمط وطول اسم الدخول، خادم HotSpot وسياسة كلمة المرور.
- [x] حفظ إعدادات التوليد في snapshot للدفعة، والتحقق من سياسة الموزع وخادم HotSpot قبل الكتابة.
- [ ] المعالج متعدد الخطوات ومعاينة القالب الجانبية غير مكتملين؛ الواجهة الحالية نموذج واحد، والكتابة محصورة بـHotSpot.

### إضافات طلب الأرشيف وواجهة التطبيق
- [x] أرشيف مرقّم بالصفحات والبحث لكل الدفعات، مع اسم آلي ونقطة التوزيع والباقة/نوع الخدمة وتواريخ الإنشاء والطباعة وعدد مرات الطباعة.
- [x] صفحة التفاصيل تعرض بيانات الدفعة وأسباب الفشل، وتعيد الطباعة باستخدام لقطة القالب وإعدادات الدفعة المحفوظة؛ إضافة إجراءات لتعطيل/تفعيل المستخدمين الناجحين على الراوتر الأصلي مع مصالحة عند غموض الأمر.
- [x] تثبيت سجل آخر طلب طباعة وعدد مرات الطباعة، وإضافة خانة اسم نقطة التوزيع كمعلومة تعريفية فقط (لا عمليات بيع أو تحصيل).
- [x] جعل القائمة الجانبية قابلة للتمرير، وإضافة ملء الشاشة ولقطة PNG والوضع الداكن المحفوظ.
- [ ] Go build/test واختبار وظائف التبديل والطباعة على RouterOS/Windows؛ لم تُجرَ بعد في هذه البيئة.

### P4 — استوديو قوالب (جزئي)
- [x] ربط القالب بنوع الخدمة، ونطاق عام/باقة/موزع وباقة؛ تفضيل القالب المخصص للموزع ثم الباقة ثم القالب العام عند التوليد.
- [x] عناصر النص واسم المستخدم وكلمة المرور والباقة والصلاحية والتاريخ وتاريخ الطباعة وQR لبيانات الدخول؛ تحريك وتغيير حجم العناصر بالسحب، مع إدخال أبعاد رقمية ومعاينة البطاقة.
- [x] حفظ نسخ ثابتة وأرشفة منطقية للقالب مع إبقاء الإصدارات القديمة واللقطة المضمنة داخل الدفعة.
- [ ] تخطيط صفحة A4 وملخص مجموع البطاقات/الهوامش، تاريخ انتهاء محسوب، وأدوات تعديل الخط/اللون/المحاذاة لكل عنصر لم تكتمل.

### P5 — الجداول (جزئي)
- [x] مكوّن صفحات موحد 10/20/50 مع أول/سابق/التالي/أخير، مستخدم في القسائم ومستخدمي الراوتر وسجل الحركات وأرشيف الدفعات.
- [x] بحث خادمي وصفحات خادمية لأرشيف الدفعات والقسائم المُدارة؛ القوائم المعروضة من RouterOS وسجل الحركات ما زالت محدودة بصفحات تحميل أولية.
- [ ] توحيد المرشحات وحالات الجداول وتوسيع pagination الخادمي لسجل الحركات ومستخدمي الراوتر.

### P6 — قبول وتسليم تجريبي
- Go: `go test ./...`, `go vet ./...`, Linux build وWindows build؛ TypeScript/build؛ فحوص migrations والتصدير والطباعة.
- تجربة طباعة فعلية/حفظ PDF على Windows: عدد الصفحات يساوي الحساب، لا تكرار، مقاس mm صحيح، وخط عربي واضح.
- اختبار RouterOS v6 و7: ملفات، إضافة/قراءة/تعطيل HotSpot، انقطاع بعد الكتابة، timeout ومصالحة. لا تفعيل UM write.
- اختبار قبول المستخدم: دفعة 20 و60 و61، تحديد موزع/بادئة/كلمة مرور وخادم، وتحقيق سجلات الراوتر وقاعدة التطبيق وPDF.

## ترتيب العمل

1. P0 قبل أي تحسينات واجهة، لتثبيت الثقة في العدد والطباعة.
2. P1 وP2 لتثبيت نماذج العرض والملكية والتسعير.
3. P3 لبناء معالج توليد يعتمد تلك النماذج ويكتب فقط HotSpot.
4. P4 لربط التصميم بالباقة/الموزع والدفعات بشكل حتمي.
5. P5 لتوحيد الوصول إلى السجلات، ثم P6 للتجربة الميدانية.

لا تعتبر أي مرحلة مقبولة بمجرد نجاح واجهة البناء؛ يلزم اختبارها على بيئة Go وجهاز RouterOS حقيقي، خصوصاً عمليات الكتابة والطباعة.
